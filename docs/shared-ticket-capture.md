# Shared ticket capture

NFL and NHL observations are captured once and delivered independently to
PythonAnywhere and the free site's TiDB database. GitHub Pages publishes the
committed TiDB data. MLB capture remains paused; its stored history stays visible.

## Capture and delivery

`Collect ticket prices` owns capture. PythonAnywhere's existing dispatcher and
the free GitHub timer request this same workflow. A per-sport gate, inside the
existing collector lock, permits one capture attempt per UTC half-hour. A failed
attempt still consumes that slot. Explicit manual repair can override the gate.

The default browser is stock headed WebKit. It opens the public team page,
clicks the visible event link, and reads the inventory response generated by
the event page. It requires a complete, unfiltered inventory response, the
correct production ID, matching title and venue, and the official UTC event
time. Access-denied responses, authentication requirements, rate limits, and
visible challenges stop further WebKit navigation in that process.

Before uploading, the collector saves the immutable public observation and its
original capture timestamp. PythonAnywhere returns a digest of the ticket rows
actually stored. A separate job, using only TiDB credentials, imports the same
observation and verifies the committed prices, counts, event, and capture slot.
Missing delivery acknowledgments retain the payload for replay. A different
observation already stored in the same slot is a reported conflict; it is never
overwritten or relabeled as the new observation.

Separate producer and consumer cache namespaces prevent an older delivery job
from replacing newer capture state. Pending observations are not trimmed to
meet storage budgets. Both deliveries must be acknowledged before the payload
can be replaced by a compact receipt.

## Publication and diagnosis

Publication runs after a capture or delivery attempt, including partial failures.
Successful duplicate timer runs do not force publication. The publisher waits
for the exact generated version to appear on Pages before removing its upload
artifact. Data freshness checks remain independent and can fail even when the
new website version was successfully published.

The October 8 investigation found native Vivid inventory 404 responses while
the event documents loaded successfully. Pre-migration Chrome code also failed;
the evidence does not establish a blanket computer ban or prove Vivid's internal
reason for the response. Four distinct NFL/NHL games passed the production
WebKit adapter canary in run `37728372483`, returning complete native inventories
of 926, 2,019, 1,018, and 1,203 listings. This is a bounded live test, not a promise
that every future provider request will succeed.

For troubleshooting, distinguish capture coverage, pending delivery, stored-row
conflicts, Pages version propagation, and stale game data. Retain original
timestamps when replaying saved observations; a later upload is not a new price
capture. The manual stock-browser canary performs no database writes.
